# Astro i18n Best Practices

This document outlines the current best practices for implementing internationalization (i18n) in Astro projects based on official documentation and community wisdom as of 2025. Updated to include the latest Astro v4.6.0+ features and content collections integration.

## Core Best Practices

### 1. Use Astro's Built-in i18n Configuration

Configure locales in `astro.config.mjs` with flexible routing strategies:

```javascript
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  i18n: {
    locales: ['en', 'zh'],
    defaultLocale: 'en',
    routing: {
      prefixDefaultLocale: false,
      redirectToDefaultLocale: false
    },
    fallback: {
      zh: 'en'
    }
  }
});
```

**Routing Strategies:**
- **Automatic Mode** (default): Astro handles routing and middleware automatically
- **Manual Mode** (`routing: 'manual'`): Full control over i18n middleware for complex use cases
- **Prefix Control**: `prefixDefaultLocale` determines URL structure for default locale
- **Fallback Content**: Define fallback locales when translations are missing

### 2. Content Organization Strategies

**Option A: File-based Routing (Traditional)**
```
src/pages/              # Default locale (English)
├── posts/
├── about.astro
└── index.astro

src/pages/zh/           # Chinese locale  
├── posts/
├── about.astro
└── index.astro
```

**Option B: Content Collections (Recommended for Blogs)**
```
src/content/
├── blog/
│   ├── en/
│   │   ├── post-1.md
│   │   └── post-2.md
│   └── zh/
│       ├── post-1.md
│       └── post-2.md
└── config.ts

src/pages/
├── blog/
│   └── [...slug].astro
└── zh/
    └── blog/
        └── [...slug].astro
```

**Key Principles:**
- **Content Collections**: Preferred for blog posts and content-heavy sections
- **Consistent Structure**: Use identical filenames across locale directories
- **Performance**: Content collections offer better type safety and build performance
- **Flexibility**: Dynamic routing with content collections supports complex multilingual scenarios

### 3. Translation Management

#### Static Text Translations
- Store translations in dedicated files (e.g., `src/locales/translations.ts`)
- Implement fallback mechanisms to default locale when translations are missing
- Use a translation function like `useTranslations()` for dynamic content

```typescript
// src/locales/translations.ts
export const translations = {
  en: {
    'nav.home': 'Home',
    'nav.about': 'About',
    // ...
  },
  zh: {
    'nav.home': '首页',
    'nav.about': '关于',
    // ...
  }
};
```

#### Content Collections Implementation (Recommended)

Content collections provide superior type safety, performance, and developer experience for multilingual content:

```typescript
// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blogCollection = defineCollection({
  type: 'content',
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.date(),
    author: z.string(),
    tags: z.array(z.string()),
    image: z.object({
      url: z.string(),
      alt: z.string()
    }),
    locale: z.enum(['en', 'zh']).optional(),
    translationKey: z.string().optional() // Link related posts across locales
  })
});

export const collections = { blog: blogCollection };
```

**Benefits:**
- **Type Safety**: Zod schema validation for all content
- **Performance**: Build-time processing and optimization
- **Fallback Support**: Automatic content fallback when translations are missing
- **Flexible Queries**: Advanced filtering and sorting capabilities
- **Translation Linking**: Connect related posts across different locales

### 4. Advanced i18n API Functions (v4.6.0+)

Astro provides a comprehensive set of i18n utilities from the `astro:i18n` module:

```typescript
// Import from astro:i18n
import {
  getRelativeLocaleUrl,
  getAbsoluteLocaleUrl,
  getRelativeLocaleUrlList,
  getAbsoluteLocaleUrlList,
  getPathByLocale,
  getLocaleByPath,
  redirectToDefaultLocale,
  redirectToFallback,
  notFound,
  middleware,
  requestHasLocale
} from 'astro:i18n';
```

**Core URL Functions:**
```typescript
// Generate URLs for specific locales
const frenchUrl = getRelativeLocaleUrl('fr', '/blog/post-1');
const absoluteUrl = getAbsoluteLocaleUrl('zh', '/about');

// Get all locale URLs for a path
const allUrls = getRelativeLocaleUrlList('/contact');
// Returns: ['/contact', '/zh/contact', '/fr/contact']
```

**Advanced Manual Routing (requires `routing: 'manual'`):**
```typescript
// In middleware or pages
export async function GET(context) {
  const { request } = context;
  
  // Check if URL contains a valid locale
  if (!requestHasLocale(request)) {
    return redirectToDefaultLocale(context);
  }
  
  // Handle fallback to other locales
  return redirectToFallback(context);
  
  // Or return 404 for missing content
  return notFound(context);
}
```

### 5. Routing Strategies and Performance

#### Automatic vs Manual Routing

**Automatic Mode (Default):**
```javascript
// astro.config.mjs
export default defineConfig({
  i18n: {
    locales: ['en', 'zh'],
    defaultLocale: 'en',
    routing: {
      prefixDefaultLocale: false
    }
  }
});
```

**Manual Mode (Advanced Control):**
```javascript
// astro.config.mjs  
export default defineConfig({
  i18n: {
    locales: ['en', 'zh'],
    defaultLocale: 'en',
    routing: 'manual'
  }
});

// src/middleware.ts
import { middleware } from 'astro:i18n';
export const onRequest = middleware();
```

#### Performance Optimization
- **Static Generation**: Use `export const prerender = true` for static content
- **Content Collections**: Filter by locale during build for better performance
- **Lazy Loading**: Load translations only for the current locale
- **Build-time Processing**: Leverage Astro's build-time optimizations for i18n content

### 6. Language Switching and Dynamic Content

#### Modern Language Switcher Implementation

```astro
---
// src/components/LangSwitcher.astro
import { getRelativeLocaleUrlList } from 'astro:i18n';

const currentPath = Astro.url.pathname;
const localeUrls = getRelativeLocaleUrlList(currentPath);
const currentLocale = Astro.currentLocale || 'en';

const localeNames = {
  en: 'English',
  zh: '中文',
  fr: 'Français'
};
---

<div class="lang-switcher">
  {Object.entries(localeUrls).map(([locale, url]) => (
    <a 
      href={url} 
      class:list={['lang-option', { active: locale === currentLocale }]}
      hreflang={locale}
    >
      {localeNames[locale]}
    </a>
  ))}
</div>
```

#### Dynamic Content with Collections

```astro
---
// src/pages/blog/[...slug].astro
import { getCollection, type CollectionEntry } from 'astro:content';

export async function getStaticPaths() {
  const posts = await getCollection('blog');
  
  return posts.map((post) => ({
    params: { slug: post.slug },
    props: { post },
  }));
}

const { post } = Astro.props;
const currentLocale = Astro.currentLocale;

// Find related posts in other locales
const allPosts = await getCollection('blog');
const relatedPosts = allPosts.filter(p => 
  p.data.translationKey === post.data.translationKey && 
  p.data.locale !== currentLocale
);
---
```

### 7. Metadata and SEO Optimization

- Set proper `lang` attributes on HTML elements
- Include hreflang tags for all available locales
- Provide localized Open Graph and meta tags
- Ensure proper canonical URLs for localized content

```astro
<!-- src/layouts/Layout.astro -->
<html lang={currentLocale}>
<head>
  {Object.entries(locales).map(([code, name]) => (
    <link rel="alternate" hreflang={code} href={getLocalizedUrl(code, currentPath)} />
  ))}
</head>
```

## Implementation Checklist

When setting up i18n in an Astro project:

**Configuration & Setup:**
- [ ] Configure `astro.config.mjs` with appropriate i18n settings
- [ ] Choose between automatic or manual routing based on complexity
- [ ] Set up fallback locales for missing content
- [ ] Configure content collections (recommended for blogs)

**Content Organization:**
- [ ] Create proper folder structure with locale directories
- [ ] Implement translation system with fallback mechanism
- [ ] Set up content collections with locale-aware schemas
- [ ] Ensure consistent file naming across locales

**Routing & Navigation:**
- [ ] Set up routing and middleware configuration
- [ ] Create language switcher using modern i18n APIs
- [ ] Implement locale-aware internal linking
- [ ] Test dynamic route generation

**SEO & Performance:**
- [ ] Implement SEO metadata and hreflang tags
- [ ] Set up proper `lang` attributes and Open Graph tags
- [ ] Configure static generation for performance
- [ ] Test content fallback behavior

**Advanced Features:**
- [ ] Implement manual routing if needed for complex scenarios
- [ ] Set up translation linking between related content
- [ ] Configure automatic locale detection (optional)
- [ ] Test error handling and 404 scenarios

## Common Pitfalls to Avoid

1. **Inconsistent File Naming**: Use same file names across locale directories
2. **Missing Fallbacks**: Always provide fallback to default locale
3. **Broken Internal Links**: Use modern i18n API functions instead of manual URL construction
4. **Poor SEO**: Implement proper hreflang tags and locale-specific metadata
5. **Complex Routing**: Start with automatic mode; only use manual for advanced cases
6. **Content Collections Misuse**: Don't mix file-based and collection-based approaches for the same content type
7. **Performance Issues**: Use static generation and build-time processing for better performance
8. **Missing Type Safety**: Leverage Zod schemas in content collections for type safety
9. **Hardcoded URLs**: Always use i18n API functions for URL generation
10. **Incomplete Translation Linking**: Set up proper translation keys to connect related content

## Migration from Legacy i18n

When migrating from custom i18n implementations:

**From File-based to Content Collections:**
1. Create content collection schema with locale support
2. Move markdown files to `src/content/[collection]/[locale]/` structure
3. Update page components to use `getCollection()` instead of `import.meta.glob()`
4. Add translation keys to link related content across locales

**From Custom Routing to Astro i18n:**
1. Start with automatic mode configuration in `astro.config.mjs`
2. Replace custom URL generation with `astro:i18n` functions
3. Update language switchers to use `getRelativeLocaleUrlList()`
4. Migrate custom middleware to Astro's built-in i18n middleware

**Migration Steps:**
1. **Audit Current Implementation**: Document existing routes, translations, and content structure
2. **Incremental Migration**: Migrate one section at a time (e.g., start with blog posts)
3. **Maintain Backward Compatibility**: Keep old routes working during transition
4. **Test Thoroughly**: Verify all links, fallbacks, and SEO metadata work correctly
5. **Performance Check**: Ensure new implementation is as fast or faster than legacy system
