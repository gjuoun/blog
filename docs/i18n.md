# Astro i18n Best Practices

This document outlines the current best practices for implementing internationalization (i18n) in Astro projects based on official documentation and community wisdom as of 2025.

## Core Best Practices

### 1. Use Astro's Built-in i18n Configuration

- Configure locales in `astro.config.mjs` with proper routing strategy (prefix vs subdomain)
- Set `prefixDefaultLocale: false` for English-first sites
- Use `middleware: true` for automatic locale detection and redirects

```javascript
// astro.config.mjs
import { defineConfig } from 'astro/config';

export default defineConfig({
  i18n: {
    locales: ['en', 'zh'],
    defaultLocale: 'en',
    prefixDefaultLocale: false,
    middleware: true
  }
});
```

### 2. File Structure Organization

Organize content by language with consistent file naming:

```
src/pages/              # Default locale (English)
├── posts/
├── about.astro
└── index.astro

src/pages/zh/           # Chinese locale  
├── posts/
├── about.astro
└── index.astro
```

**Key Principles:**
- Use identical filenames across locale directories for automatic content association
- Maintain consistent directory structure across locales
- Place default locale files directly in `src/pages/`

### 3. Translation Management

#### Static Text Translations
- Store translations in dedicated files (e.g., `src/locales/translations.ts`)
- Implement fallback mechanisms to default locale when translations are missing
- Use a translation function like `useTranslations()` for dynamic content

```typescript
// src/locales/translations.ts
export const translations = {
  en: {
    'nav.home': 'Home',
    'nav.about': 'About',
    // ...
  },
  zh: {
    'nav.home': '首页',
    'nav.about': '关于',
    // ...
  }
};
```

#### Content Collections (Recommended for Blog Posts)
- Use Astro's built-in content collections for blog posts and other content-heavy sections
- Leverage collection queries for better i18n integration
- Take advantage of automatic fallback content when translations are missing

```astro
// src/content/config.ts
import { defineCollection, z } from 'astro:content';

const blogCollection = defineCollection({
  schema: z.object({
    title: z.string(),
    description: z.string(),
    pubDate: z.date(),
    // ...
  })
});

export const collections = { blog: blogCollection };
```

### 4. URL Consistency and SEO

- Use identical filenames across locale directories for automatic content association
- Implement locale-aware internal linking functions
- Set up proper hreflang tags for SEO optimization

```typescript
// src/utils/routes.ts
export function getRelativeLocaleUrl(locale: string, path: string) {
  const base = locale === 'en' ? '' : `/${locale}`;
  return `${base}${path}`;
}
```

### 5. Routing Strategy

#### Prefix Routing (Recommended)
- Prefix routing (`/zh/`) is preferred over subdomains for most cases
- Better SEO and simpler configuration
- Easier to implement language switchers

#### Configuration Options:
- **Automatic Locale Detection**: Set `middleware: true` for automatic redirects based on browser preferences
- **Explicit User Control**: Don't use middleware if you want users to have manual control over language selection
- **Fallback Behavior**: Configure appropriate fallbacks when content is missing in a locale

### 6. Language Switching

Provide a clear language switcher that:
- Shows current language
- Links to equivalent pages in other languages
- Maintains navigation state when switching languages

```astro
<!-- src/components/LangSwitcher.astro -->
<div class="lang-switcher">
  <a href={enUrl}>English</a>
  <a href={zhUrl}>中文</a>
</div>
```

### 7. Metadata and SEO Optimization

- Set proper `lang` attributes on HTML elements
- Include hreflang tags for all available locales
- Provide localized Open Graph and meta tags
- Ensure proper canonical URLs for localized content

```astro
<!-- src/layouts/Layout.astro -->
<html lang={currentLocale}>
<head>
  {Object.entries(locales).map(([code, name]) => (
    <link rel="alternate" hreflang={code} href={getLocalizedUrl(code, currentPath)} />
  ))}
</head>
```

## Implementation Checklist

When setting up i18n in an Astro project:

- [ ] Configure `astro.config.mjs` with appropriate i18n settings
- [ ] Create proper folder structure with locale directories
- [ ] Implement translation system with fallback mechanism
- [ ] Set up routing and middleware configuration
- [ ] Create language switcher component
- [ ] Implement SEO metadata and hreflang tags
- [ ] Test content fallback behavior
- [ ] Verify proper redirect handling
- [ ] Ensure consistent file naming across locales

## Common Pitfalls to Avoid

1. **Inconsistent File Naming**: Use same file names across locale directories
2. **Missing Fallbacks**: Always provide fallback to default locale
3. **Broken Internal Links**: Use locale-aware URL generation functions
4. **Poor SEO**: Implement proper hreflang tags and metadata
5. **Complex Routing**: Stick with prefix routing unless you have specific requirements
6. **Ignoring Browser Preferences**: Consider automatic locale detection with middleware

## Migration from Legacy i18n

When migrating from custom i18n implementations:

1. Gradually migrate to Astro's built-in i18n features
2. Consider switching to content collections for blog posts
3. Maintain backward compatibility during transition
4. Test thoroughly to ensure no broken links or content loss
